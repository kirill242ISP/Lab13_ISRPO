# Практическая работа №5. Список у ворот

1. **Кто теперь проверяет повтор при добавлении и почему не Program?**
   Повтор проверяет сама гильдия в методе `AddHero`. Если вынести правило в `Program`, любой другой участок кода сможет добавить дубликат напрямую, обойдя проверку.
2. **Когда FindHeroByName возвращает null?**
   Когда передана пустая строка (или строка из одних пробелов) либо когда цикл перебрал весь список `_heroes` и не нашёл ни одного совпадения.
3. **Зачем очищать запрос, если имена героев уже очищены?**
   Поисковый запрос поступает извне (например, `" аРтЁм "`) и может содержать пробелы по краям; без `Trim()` сравнение не сработает.
4. **Почему MemberCount не хранит число, а вычисляет его?**
   Вычисляемое свойство при каждом обращении берёт актуальное `_heroes.Count`, поэтому исключена ошибка рассинхронизации счётчика при добавлении или удалении.
5. **Удаление из гильдии уничтожает героя?**
   Нет, `Remove` убирает ссылку на героя только из списка `_heroes`, а сам объект остаётся в памяти и доступен через другие переменные.
6. **Почему private-поле не защищено, если вернуть его из метода?**
   Модификатор `private` скрывает только имя поля, но если вернуть ссылку на сам список `_heroes`, внешний код сможет изменить его содержимое (например, вызвать `Clear()`).

**Трассировка:** прогноз `True`, `False`, `True`, `True`, `1`, `2`, `True`, факт полностью совпал с прогнозом, ошибок при трассировке не было. В фрагменте создано 3 объекта `Hero`, в гильдии остался 1 («Второй»). `snapshot.Count` равен `2`, так как копия списка была получена до удаления «Первого».
**Ошибка 1:** `return null;` внутри цикла завершает весь метод сразу после первого несовпадения; исправление — убрать `return null;` из цикла и оставить только после него.
**Ошибка 2:** метод возвращает ссылку на сам список `_heroes`, из-за чего проба покажет «В гильдии: 0»; исправление — создавать новый список `List<Hero>` и копировать в него ссылки.
**Самостоятельный шаг:** `FindStrongest` возвращает `Hero?`, потому что в пустой гильдии самого здорового героя нет (`null`), а `CountHealthy` возвращает `int`, так как количество всегда выражается числом (для пустой гильдии это `0`). При получении `null` вызывающий код обязан проверить результат (`if (strongest != null)`) перед чтением свойств, чтобы избежать `NullReferenceException`.

### Личный проект
* **Ключ:** выбрано название товара (`Name`) без учёта регистра и пробелов по краям, так как на складе не должно быть дублирующихся карточек одного товара.
* **Когда подведёт:** если на склад поступят два разных товара с одинаковым названием (например, два «Железных щита» разных производителей или по разной цене), второй товар будет отклонён как дубликат.
* **Обработка null:** если товар не найден, `FindProductByName` возвращает `null`. В `Program` результат сохраняется в переменную `Product?` и проверяется через `if (foundProduct != null)` перед обращением к свойствам товара.
